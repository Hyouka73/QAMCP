## Correcciones requeridas

### C1. Custodia posicionable y respaldo criptográfico

**AR-27/28/39 · TEC-13/14/16/18 · XET-06/07 · capturador → custodia → visor.**

- **Principal.** El código fuente etiquetado de **Tink Java 1.24.0** confirma `newSeekableDecryptingChannel` y la autenticación de los bytes devueltos. Su contrato deja abierta la autenticación de `size()`. Por ello, para `HEAD`, `206`, `Content-Range` y `416`, el visor debe usar la longitud comprometida en el manifiesto autenticado y verificar su concordancia con el cierre autenticado del objeto sellado y la generación vigente. Una lectura parcial válida acredita los segmentos leídos. La atestación AR-28 requiere además la autoridad de sellado y su ancla de confianza. [API Tink Java 1.24.0](https://github.com/tink-crypto/tink-java/blob/v1.24.0/src/main/java/com/google/crypto/tink/StreamingAead.java) · [Análisis de Streaming AEAD](https://eprint.iacr.org/2020/1019.pdf)
- **Respaldo concreto.** Incorporar **Tink C++ 2.4.0** como candidato cuando falle la ruta Java/JRE. La API `NewDecryptingRandomAccessStream`, su implementación en el wrapper y la documentación del proyecto para Windows, macOS y Ubuntu dan base para calificarlo. La API C++ también distingue el tamaño informado de la comprobación del bloque final. Debe probarse con el proveedor criptográfico y ABI elegidos, el mismo contrato de custodia y KEK, y por SO/CPU obligatorio. Puede resolver un impedimento de Java o del JRE. Una limitación común de formato o custodia afectaría a ambos. Para esa contingencia, **age Go 1.3.2** merece figurar como candidato de formato distinto: `DecryptReaderAt` autentica el último bloque antes de devolver la longitud. Su integración con KEK, vinculación al manifiesto y a la generación, rotación, revocación y distribución siguen abiertas. Su BSD-3-Clause corresponde a la biblioteca. [API Tink C++ 2.4.0](https://github.com/tink-crypto/tink-cc/blob/v2.4.0/tink/streaming_aead.h) · [Wrapper C++](https://github.com/tink-crypto/tink-cc/blob/v2.4.0/tink/streamingaead/streaming_aead_wrapper.cc) · [Código de age 1.3.2](https://github.com/FiloSottile/age/blob/v1.3.2/age.go) · [Licencia de age](https://github.com/FiloSottile/age/blob/v1.3.2/LICENSE)
- **Garantía y fase.** En **EXP-06a**, calificar por separado el productor **C o A**, la prevención desde el primer cuadro, la protección desde la primera escritura y la custodia autenticada con memoria acotada. Incluir trazas, perfiles, cachés, staging del códec y caída abrupta. Un canario capturado transitoriamente veta la celda. En **EXP-06c/E6**, exigir reproducción positiva, seek al 10/50/90 %, cruce de segmento, rechazo de sustitución/truncamiento y cese de emisión tras revocación, dentro de los presupuestos medidos. La supresión preventiva protege la superficie afectada y la garantía de captura sigue pendiente. Si ninguna composición supera EXP-06a en una celda obligatoria, conservar el bloqueo de G0/G1 y elevar cualquier cambio de alcance. [Fe de AR-27](https://github.com/Hyouka73/QAMCP/blob/e12927104051dffba149dd9824ac517863eee421/docs/qap-architecture/cierre-av-01/fe-correcciones-ar27.md) · [Protocolos EXP-06a/c](https://github.com/Hyouka73/QAMCP/blob/e12927104051dffba149dd9824ac517863eee421/docs/qap-architecture/cierre-av-01/protocolos-exp-06-ac.md)
