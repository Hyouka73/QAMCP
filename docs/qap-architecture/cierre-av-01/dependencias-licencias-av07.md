## Runtime y SQLite

`node:sqlite` entró en 22.5 con flag experimental, 22.13 quitó requisito de flag, 22.16.0 oficial aporta FTS5 como dato histórico. El preflight vigente comprueba compile option en memoria, sin certificar las funciones exactas ni cada binary de proveedor. Recomendar evaluar Node 24.22.3 Krypton (LTS, fuente y checksum oficial), con builtin de partida. LTS 26.13.1 puede ser brazo alterno si mejora soporte SDK/OCI/ABI, además de una LTS de respaldo compatible si el proveedor lo requiere; seleccionar según soporte de SO, parche y operación. Medir y alinear engines/target/types y API real de SQLite. La línea 18 del manifest/AGENTS no satisface los stores. [Versiones Node](https://nodejs.org/en/about/previous-releases) · [Distro 24.22.3](https://nodejs.org/en/download/archive/v24.22.3) · [Release de seguridad del 11 de noviembre y cambios TLS/HTTP/SQLite](https://nodejs.org/en/blog/release/v24.22.3) · [SQLite API fijada](https://github.com/nodejs/node/blob/v24.22.3/doc/api/sqlite.md) · [FTS5 en 22.16.0](https://github.com/nodejs/node/blob/v22.16.0/deps/sqlite/sqlite.gyp).

| Driver | Beneficio y riesgo | Decisión |
| --- | --- | --- |
| node:sqlite | Sin addon externo, SQLite y parches emparejados al build Node, API síncrona y evolución por minor. | Candidato inicial. Escritor dedicado/cola acotada evita bloqueo del loop de transporte. Acreditar backup, options y schema con el binario real. |
| better-sqlite3 13.2.0 | MIT, Node ≥22, control de versión SQLite separado, addon con prebuild o build local. Costos de cadena binaria, plataforma, ABI, actualizaciones y notices. | Brazo alternativo si el builtin incumple una garantía. Prebuild firmado/verificable por celda e instalación limpia. No fallback silencioso. [Registro](https://registry.npmjs.org/better-sqlite3/13.2.0) · [Release](https://github.com/WiseLibs/better-sqlite3/releases/tag/v13.2.0). |

Doctor en cada artefacto: runtime, `process.execPath`, hash, `process.versions.modules/napi`, `sqlite_version()` y `sqlite_source_id()`, compile options, FTS5 unicode y reconstrucción, FK, CAS/transacciones, backup/restore, WAL/locks, busy/retry acotado, disco lleno y checkpoint/corte. No usar volúmenes de red para WAL. Seleccionar build con corrección WAL-reset (3.51.3+ en la rama aplicable, o backports 3.44.6/3.50.7 documentados), considerando versión efectiva y no la existencia de un solo escritor nominal. Probar continuidad de revocación y ACK ante caída con política de durabilidad explícita. [Corrección SQLite](https://www.sqlite.org/wal.html#the_wal_reset_bug).

## Distribución y principal de confianza

| Opción | Ventaja | Costo o barrera |
| --- | --- | --- |
| Bundle monolito por entrada | Reduce dependencias publicadas, reutiliza tsup CLI. | Duplicación MCP/CLI, opcionales nativos y assets difíciles y auditoría de licencias. Debe probar un solo núcleo/escritor. |
| Paquetes publicados versionados | Límites/reutilización claros y actualización por dependencia. | Requiere publicar y autenticar internos o registry privado, coordinación de versiones y offline. `workspace:*` no se resuelve en npm sin empaquetar o dar acceso. |
| Distribución local autocontenida por variante, con capacidades separadas | Candidato recomendado. Una identidad de núcleo, dos lanzadores, runtime y supervisor colocados una vez; navegador/modelos/OCR/códecs vía caché versionada. | Mayor gestión por plataforma, firma y permisos bootstrap diferenciados. No introduce servicio remoto/daemon permanente. npm puede ser vehículo reproducible si tarball exacto y dependencias disponibles, nunca `npx latest`. |

MCP 2.1.3 `qap-mcp` → dist/server.js, CLI 2.1.3 `qap` → dist/entrypoint.js, sin engines ni exports en manifests. Ambos declaran publicación pública y files dist, sin scripts propios postinstall. El lock autoriza builds de esbuild y keytar; el instalador nativo de keytar queda fuera del arranque normal en el diseño nuevo. Las rutas main de MCP y CLI y el d.ts de MCP requieren versión explícita en la prueba de consumidores. `files`, shebang y dist no acreditan assets. Estampa MCP de TS por carpeta y SHA JS omite toda la cadena (assets/copias, lock, nativos y variantes) y horario introduce metadato variable. Auditar lifecycle scripts y root `allowBuilds`; npm y pnpm no deben convertir dependencias faltantes en descarga opaca durante arranque. Validar resolución privada y lock/pack efectivos fuera de monorepo. [npm pack](https://docs.npmjs.com/cli/v11/commands/npm-pack) · [Protocolo workspace](https://pnpm.io/workspaces#workspace-protocol-workspace).

El registro actual en `packages/mcp/src/register.ts` identifica `qap:<proyecto>` y usa npx sin pin para CLI mcp, solo Cursor y Claude Desktop. Lee JSON previo, pero reescribe la configuración completa, dry-run imprime el objeto entero y esa ruta carece de prueba de exclusión concurrente, ownership de alias y desregistro simétrico. La consulta del registry público de npm para ambas versiones 2.1.3 devolvió 404 desde el entorno de auditoría. La declaración publishConfig es intención de empaquetado. Probar registro desde lanzador local autenticado y actualización CAS del ámbito propio por HOST D13, sin volcar configuraciones ajenas. [Registro actual](https://github.com/Hyouka73/QAMCP/blob/45401c45f91b3cd4944f372491e3c3c9f12ec56d/packages/mcp/src/register.ts).

Por plataforma comparar instalador firmado Windows (MSI o MSIX si encaja el supervisor) frente a archivo autenticado y registro separado; paquete macOS firmado/notarizado frente a archivo autenticado con bootstrap explícito; Linux paquete deb/rpm según distro o archivo firmado con manifest y unidades elegibles. En todos los casos, actualizar en slot nuevo, verificar manifest, cambiar puntero solo tras doctor, registrar propiedad y conservar datos. Rechazar rollback a versión revocada o incompatible con esquema. La separación de AR-28 debe negar acceso del HOST a claves, recurso de captura y DB, incluso al compartir equipo. Supervisor fuera del árbol que domina Stdio, brokers de autoridad, egress y secretos con identidad propia. Exponer IPC autenticado con prueba de permiso y generación. VM añade imagen, copias, virtualización, latencia/huella, pantalla y puente IO; medir cold/warm, recursos y limpieza. Sandbox, a11y, D11 y cobertura por SO conservan sus compuertas. Bootstrap privilegiado donde requiera alta de cuenta/servicio, dependencias del sistema o hipervisor; operación cotidiana de mínimos privilegios.
